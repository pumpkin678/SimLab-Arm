# 教学任务说明

本页记录教学目标、成员职责和待确定的任务要求。正式工况、验收阈值及提交格式尚待确定；当前仓库提供可运行的仿真与采集框架，Arm 仍是零力矩骨架。

## 教学目标

围绕同构控制器提供的六轴目标位置，让成员学习机械臂规划与控制，使机械臂能够快速、稳定地跟随目标，并能解释自己的算法选择与实际表现。训练在仿真中完成，获得的经验用于后续实物机械臂开发。

当前通过 GUI 手动输入和程序工况构造目标序列，成员不需要实际操作者输入即可开始调试。

学习内容包括理解关节目标和反馈、设计内部规划与控制过程、通过数据观察误差与振荡，以及分析模型约束和力矩限制对表现的影响。具体算法路线由成员设计，框架不预设 Arm 内部管线。

## 框架与成员职责

| 部分 | 当前职责 |
| --- | --- |
| 框架 | 模型与 MuJoCo 接入、目标输入、物理周期调度、关节反馈和力矩映射、GUI、benchmark 执行及统一 trace |
| 成员实现 | 在 `simulation/arm/` 内实现 Arm 的规划和控制逻辑，管理内部状态，在 update 中返回请求力矩，在 reset 中恢复内部状态 |
| 教学任务 | 指定参考工况、关注的表现、比较方法和验收条件；这些内容尚未定稿 |

实现从 [Arm](../simulation/arm/arm.hpp) 接入。成员可以自行组织 `simulation/arm/` 内部代码；共用输入输出接口、模型和记录格式是不同实现进行对比的基础。

### 实现边界

外部只提供目标位置，内部所需的参考加工、规划与控制由成员设计。接口字段、单位、周期时序和复位契约见 [架构说明](architecture.md#控制周期与接口)，坐标、零位和模型约束见 [资产说明](../assets/README.md)。

参考实现的参数和调试效果不自动构成教学要求；正式任务需要另行明确允许修改的范围和验收条件。

## 开发与观察

1. 按 [工具说明](../tools/README.md) 完成构建，运行手动 GUI，熟悉目标输入、暂停、复位和状态读数。
2. 在 Arm 内实现规划与控制，通过手动调整目标观察机械臂响应，并在需要时开启 Trace。
3. 使用 benchmark 的程序参考重复运行，结合 CSV 中的目标、反馈、请求与实际力矩分析表现。
4. 根据记录解释算法的有效范围、问题和改进依据，保留能够对应代码与工况的结果。

`joint_sine` 是接入示例，不代表真实操作者，也不是已确定的教学验收集。

教学评价关注跟随误差、响应速度、振荡和力矩使用情况，需要结合任务条件解释，当前没有自动性能评分。运行状态和采样语义见 [Benchmark 与采集](benchmark.md)；CTest 检查框架契约，不替代教学任务验收。

## 成果记录建议

正式提交格式确定前，开发过程可保留以下内容，便于复核和后续讨论：

| 内容 | 用途 |
| --- | --- |
| 实现源码及对应版本或修改代码 | 确认记录来自哪份实现 |
| 算法与参数说明 | 解释内部规划、控制过程及参数选择依据 |
| 运行条件 | 记录模型、case ID、实际参数和相关模型修改 |
| [运行产物](benchmark.md#录制产物与结果) | 核对输入、反馈、输出和执行情况 |
| 结果解释 | 说明观察到的效果、失败情况与已知限制 |

这些是当前的记录建议，统一提交目录、命名和最终交付要求尚未确定。

## 待确定的教学内容

| 项目 | 需要确定的问题 |
| --- | --- |
| 教学工况 | 采用哪些关节目标、变化速度、分段安排与持续时间，如何覆盖期望的跟随情景 |
| 验收指标 | 用哪些指标描述快速、稳定与跟踪精度，如何区分移动段与保持段，以及相应阈值 |
| 任务安排 | 是否划分实现阶段、每阶段提交什么，以及允许调整的模型或参数范围 |
| 对照方式 | 如何使用参考实现进行比较，以及需要保留哪些对照数据 |

任务确认后，在本页维护学习要求、验收指标和交付约定。工况组织与记录格式见 [Benchmark 与采集](benchmark.md)。
